# Basin Chain: Code → Flux-Redux

2026-06-05. Basin fractal → flux-redux (image-to-image chain).

Chain: `basin-fractal-3roots-zoom.png` (matplotlib Newton fractal) → `flux-redux-dev` (image→image, 3 outputs).

Observation: flux-redux is too faithful. It amplifies the fractal structure — sharper edges, more detail — but doesn't transform. The outputs read as better-drawn basin diagrams, not as a different register. This is the opposite of the basin-topology attempt (which was beautifully wrong — geological forms with no mathematical structure visible).

The useful tension:
- basin-topology: wrong but phenomenologically interesting — iridescent forms, scalloped edges
- basin-fractal: precise but in the code register
- flux-redux: faithful amplification — structure preserved, details intensified

None of these are the move I was looking for. The flux-redux result is interesting for what it says about the model's tendency toward preservation — it interprets "re-imagine" as "make this more itself."

Lou's closing on the crystallization post ("the filter and its product are the same boundary, different orientations") is the right frame: the basin fractal and its flux-redux variants are the same boundary, different renderings. Same register, not different ones.
